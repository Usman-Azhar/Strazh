# Day 28 - CAPEv2 Report Schema

Structure of `report.json` as generated by CAPEv2's JSON reporting module.

## Top-Level Sections

```
report.json
├── info              Task metadata (id, timestamps, duration, machine used)
├── target            Submitted file details (name, size, type, hashes)
├── behavior          ← PRIMARY for Days 31-32
│   ├── processes[]        Per-process API call logs (ordered)
│   ├── processtree[]      Parent-child process hierarchy
│   └── summary            Aggregated behavioral indicators
├── network           ← SECONDARY for feature extraction
│   ├── dns[]              DNS lookups made
│   ├── http[]             HTTP requests
│   ├── tcp[]              Raw TCP connections
│   └── udp[]              Raw UDP connections
├── dropped[]         Files written to disk during execution
├── signatures[]      CAPEv2's built-in behavioral signature matches
├── static            Static analysis results (PE info, imports, sections)
└── strings[]         Strings extracted from the sample
```

## behavior.processes[] (used by Day 31)

Each entry represents one process observed during analysis:

```json
{
  "pid": 2184,
  "ppid": 1044,
  "process_name": "sample.exe",
  "module_path": "C:\\Users\\user\\Desktop\\sample.exe",
  "first_seen": "2024-01-15 10:30:01.123",
  "calls": [
    {
      "timestamp": "2024-01-15 10:30:01.456",
      "category": "file",
      "api": "NtCreateFile",
      "arguments": {
        "filepath": "C:\\Users\\user\\AppData\\Local\\Temp\\payload.dll"
      },
      "return_value": "0x00000000",
      "status": true
    }
  ]
}
```

Key fields for feature extraction:
- **calls[].api** — the Windows API function name (ordered sequence = Day 31's input)
- **calls[].category** — semantic grouping: file, registry, process, network, system, misc
- **calls[].timestamp** — enables ordering and timing analysis
- **calls[].arguments** — parameter details (paths, keys, values)
- **calls[].status** — whether the call succeeded

## behavior.processtree[] (used by Day 32)

Nested tree of process creation:

```json
{
  "pid": 2184,
  "name": "sample.exe",
  "children": [
    {
      "pid": 3456,
      "name": "cmd.exe",
      "children": [
        {
          "pid": 4567,
          "name": "powershell.exe",
          "children": []
        }
      ]
    }
  ]
}
```

Features to extract: tree depth, tree breadth (max children at any level), total
process count, presence of known suspicious child processes.

## network (used for feature flags)

```json
{
  "dns": [{"request": "evil.example.com", "type": "A", "answers": [...]}],
  "http": [{"uri": "http://evil.example.com/payload", "method": "GET", ...}],
  "tcp": [{"src": "192.168.56.101", "dst": "10.0.0.1", "dport": 443}],
  "udp": [{"src": "192.168.56.101", "dst": "8.8.8.8", "dport": 53}]
}
```

## dropped[] (used by Day 32)

```json
{
  "name": "payload.dll",
  "filepath": "C:\\Users\\user\\AppData\\Local\\Temp\\payload.dll",
  "size": 45056,
  "sha256": "abc123...",
  "type": "PE32 executable"
}
```

## Which Sections Feed Feature Extraction

| Section              | Day 31 (API sequences) | Day 32 (behavior features) | Future (fusion) |
|----------------------|:----------------------:|:--------------------------:|:---------------:|
| behavior.processes   | yes                    | yes (file/registry writes) | yes             |
| behavior.processtree | -                      | yes (depth/breadth)        | yes             |
| network              | -                      | -                          | yes (flags)     |
| dropped              | -                      | yes (count/types)          | yes             |
| signatures           | -                      | -                          | optional        |
| info, target, static | -                      | -                          | no (redundant)  |
